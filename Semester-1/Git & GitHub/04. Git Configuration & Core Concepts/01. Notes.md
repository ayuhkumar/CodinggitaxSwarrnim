## 1. Git Configuration

Before using Git, we must tell Git **who we are**.  
This information is attached to every commit we make.

### Why is configuration needed?
- Every commit stores the author’s name and email
- It helps identify who made which change
- It is required only **once** (global setup)

### Configuration Commands

```bash
# Set your name
git config --global user.name "Your Name"

# Set your email
git config --global user.email "your@email.com"
```

### Verify Configuration

```bash
# Check name
git config --global user.name

# Check email
git config --global user.email

# See all configuration
git config --list
```

> **Note:**  
> `--global` means this setting will apply to **all repositories** on your computer.  
> You do **not** need to set it again for every project.

## 2. Important Git Concepts

### 2.1 Repository (Repo)
- A **repository** is like a project folder that contains all your project files **and** the complete history of changes.
- Standard practice: **One repository = One project**

There are two types:

| Type              | Location              | Description                              |
|-------------------|-----------------------|------------------------------------------|
| **Local Repository**  | On your computer     | The copy you work on daily               |
| **Remote Repository** | On GitHub (cloud)   | The online version shared with others    |

---

### 2.2 Branch
- A **branch** is an independent line of development.
- By default, every new repository has a main branch (earlier called `master`, now usually `main`).
- Developers create different branches to work on different features or modules without disturbing the main code.

**Common use cases:**
- Working on a new feature
- Fixing a bug
- Multiple team members working on the same project

---

### 2.3 Clone
- **Cloning** means making a complete copy of a remote repository (from GitHub) to your local computer.
- It downloads all files + complete history.

**Command:**
```bash
git clone <HTTPS-URL>
```

**Example:**
```bash
git clone https://github.com/username/project-name.git
```

After cloning, you get a local version of the project.

---

### 2.4 Fork
- **Fork** means creating a personal copy of **someone else’s repository** on **your own GitHub account**.
- It is done on the GitHub website (not through Git commands).
- After forking, you can clone your forked repository and work freely.
- Commonly used when contributing to open-source projects.

| Action | Where it happens | Result |
|--------|------------------|--------|
| Fork   | On GitHub website | Copy of repo under your account |
| Clone  | On your computer  | Local copy of a repository |

---

### 2.5 Staging Area
- The **Staging Area** is an intermediate area between your working directory and the local repository.
- You first **select** (stage) the files you want to include in the next version.
- Only staged files can be committed.

**Command to stage files:**
```bash
git add .                  # Stage all changes
git add filename           # Stage a specific file
```

---

### 2.6 Commit
- A **commit** creates a new version (snapshot) of your project in the **local repository**.
- It is a permanent record of changes with a message.

**Command:**
```bash
git commit -m "Meaningful message"
```

**Important:**
- Commit happens **only locally**.
- It does **not** upload anything to GitHub.

---

### 2.7 Push & Pull (Overview)

| Action | Meaning |
|--------|---------|
| **Push** | Upload your local commits to the remote repository (GitHub) |
| **Pull** | Download the latest changes from the remote repository to your local system |

## 3. Local Repository vs Remote Repository

| Feature              | Local Repository              | Remote Repository              |
|----------------------|-------------------------------|--------------------------------|
| Location             | Your computer                 | GitHub (cloud)                 |
| Access               | Offline                       | Requires internet              |
| Purpose              | Day-to-day work               | Sharing & collaboration        |
| Created by           | `git init` or `git clone`     | Created on GitHub website      |
| Commands used        | `add`, `commit`, `log`        | `push`, `pull`, `clone`        |

---

## 4. Basic Flow of Git (Conceptual)

```
Working Directory
       ↓   (git add)
Staging Area
       ↓   (git commit)
Local Repository
       ↓   (git push)
Remote Repository (GitHub)
```

---

## 5. Key Points to Remember

1. Always configure your **name** and **email** before making commits.
2. Configuration is done only once using `--global`.
3. **Clone** = Copy remote repo to your computer.
4. **Fork** = Copy someone else’s repo to your GitHub account.
5. **Staging** = Selecting files for the next commit.
6. **Commit** = Saving a snapshot in the local repository.
7. Local repo is on your system; Remote repo is on GitHub.

## 7. Key Takeaway

> Before writing any code with Git, always set your **name** and **email**.  
> Understand the difference between **Local** and **Remote** repository.  
> Remember the flow:  
> **Working Directory → Staging Area → Local Repo → Remote Repo (GitHub)**
