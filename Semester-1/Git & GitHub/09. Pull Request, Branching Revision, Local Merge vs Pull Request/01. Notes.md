# Day 9 – Branching Revision, Local Merge vs Pull Request  

---

## Learning Goals

By the end of this session, you should be able to:

- Confidently use all basic branching commands
- Follow proper **branch naming conventions**
- Perform a **local merge**
- Understand the difference between **Local Merge** and **GitHub Pull Request**
- Create a Pull Request on GitHub
- Merge a Pull Request on GitHub

---

## 1. Revision of Branching Commands

| Action                              | Modern Command                  | Older Command                     |
|-------------------------------------|---------------------------------|-----------------------------------|
| List all branches                   | `git branch`                    | `git branch`                      |
| Switch to an existing branch        | `git switch branch-name`        | `git checkout branch-name`        |
| Create + Switch to new branch       | `git switch -c branch-name`     | `git checkout -b branch-name`     |
| Merge a feature branch into main    | `git merge feature-branch`      | `git merge feature-branch`        |
| Delete a merged branch              | `git branch -d branch-name`     | `git branch -d branch-name`       |

> **Note:** Prefer `git switch` and `git switch -c` (modern and recommended).

---

## 2. Branch Naming Convention

Good branch names are short, clear, and meaningful.

### Recommended Style:
```text
feature/login-page
feature/contact-form
bugfix/navbar-alignment
hotfix/header-crash
```

### Rules:
- Use lowercase letters
- Use hyphens (`-`) instead of spaces
- Start with a type: `feature/`, `bugfix/`, `hotfix/`
- Keep the name descriptive but short

**Bad examples:**
- `new`
- `test`
- `mybranch`
- `FinalChanges`

## 3. Local Merge Workflow (Revision)

This is what you learned in Day 8:

```bash
# 1. Make sure you are on main
git switch main

# 2. Create and switch to feature branch
git switch -c feature/about-page

# 3. Make changes → add → commit
git add .
git commit -m "Added about page"

# 4. Switch back to main
git switch main

# 5. Merge the feature branch
git merge feature/about-page

# 6. Delete the feature branch
git branch -d feature/about-page
```

**This entire process happens only on your computer (local).**

---

## 4. Local Merge vs GitHub Pull Request

| Point                    | Local Merge                          | GitHub Pull Request (PR)                  |
|--------------------------|--------------------------------------|-------------------------------------------|
| Where it happens         | On your computer                     | On GitHub website                         |
| Who can review           | Only you                             | Teammates can review                      |
| Code review              | Not possible                         | Possible                                  |
| Safety                   | Less safe for teams                  | Much safer                                |
| Used in companies?       | Rarely for main branch               | Standard practice                         |
| Command / Action         | `git merge`                          | Create PR → Review → Merge button         |

### When to use what?

- **Local Merge** → Learning / personal projects / quick experiments
- **Pull Request** → Team projects / professional work / open source

---

## 5. Professional Workflow using Pull Request

```bash
# 1. Update main
git switch main
git pull origin main

# 2. Create feature branch
git switch -c feature/services-page

# 3. Make changes, then
git add .
git commit -m "Added services page"

# 4. Push the feature branch
git push -u origin feature/services-page
```

Now go to **GitHub**.

---

## 6. How to Create a Pull Request (Step-by-step)

1. Push your feature branch to GitHub
2. Open your repository on GitHub
3. You will usually see a yellow banner: **“Compare & pull request”**
4. Click **Compare & pull request**
5. Fill in:
   - **Title** (clear and meaningful)
   - **Description** (what you changed and why)
6. Set:
   - **base:** `main`
   - **compare:** your feature branch
7. Click **Create pull request**

---

## 7. How to Merge a Pull Request (Step-by-step)

1. Open the Pull Request on GitHub
2. Review the **Files changed** tab
3. Check if everything looks correct
4. Click **Merge pull request**
5. Click **Confirm merge**
6. (Recommended) Click **Delete branch** on GitHub

---

## 8. After Merging the PR (Very Important)

Your local `main` is now outdated. Update it:

```bash
git switch main
git pull origin main
git branch -d feature/services-page
```

---

## 9. Complete Comparison of Both Workflows

### Local Merge Flow:
```
Create branch → Commit → Switch to main → git merge → Delete branch
```

### Pull Request Flow (Professional):
```
Create branch → Commit → Push branch → Create PR → Review → Merge PR → git pull → Delete branch
```

---

## 10. Key Points to Remember

1. Always use proper branch naming (`feature/...`, `bugfix/...`)
2. Never work directly on `main`
3. Local merge is good for learning
4. Pull Request is the professional way
5. After merging a PR, always run `git pull` on local main
6. Delete the feature branch both on GitHub and locally

## 11. Quick Revision Table

| Concept                     | Command / Action                          |
|-----------------------------|-------------------------------------------|
| Create + Switch branch      | `git switch -c feature/name`              |
| Switch branch               | `git switch branch-name`                  |
| Local merge                 | `git merge feature/name`                  |
| Push feature branch         | `git push -u origin feature/name`         |
| Create PR                   | On GitHub (Compare & pull request)        |

| Delete local branch         | `git branch -d feature/name`              |

---

## 12. Key Takeaway

> **Local Merge** = You merge yourself on your computer  
> **Pull Request** = You request others (or yourself) to merge through GitHub (safer + reviewable)

**Professional Habit:**
```
git pull → create feature branch → work → commit → push branch → Create PR → Merge PR → git pull → delete branch
```
