
# Full Pull Request Lifecycle • Create • Review • Rework • Merge • Cleanup • Update Local Main

## Learning Goals

- Create a feature branch, add files, commit, and push.
- Open a Pull Request (PR) on GitHub step by step.
- Review / comment on a Pull Request.
- Rework a PR after receiving review comments.
- Merge a Pull Request on GitHub.
- Delete the remote feature branch after merging.
- Update local `main` using `git fetch` + `git merge` (or `git pull`).
- Delete the local feature branch safely.

## 1. Complete Pull Request Lifecycle (Overview)

Today we practiced the full professional workflow that teams use every day:

1. Create feature branch → Add files → Commit → Push  
2. Open Pull Request on GitHub  
3. Reviewer comments / requests changes  
4. Developer reworks (new commits) and pushes again  
5. Reviewer approves → Merge the PR  
6. Delete remote feature branch  
7. Update local main (fetch + merge or pull)  
8. Delete local feature branch  

## 2. Create Feature Branch, Add File, Commit & Push

We practiced with three examples: `feature/sign-up`, `feature/sign-in`, and `feature/dashboard`.

### Example 1: feature/sign-up

```bash
# Start from updated main
git checkout main
git pull origin main

# Create and switch to feature branch
git checkout -b feature/sign-up

# Create the file (sign-up.html)
git add sign-up.html
git commit -m "Add sign-up page"
git push -u origin feature/sign-up
```

### Example 2 & 3 (same pattern)

```bash
git checkout -b feature/sign-in
# create sign-in.html → add → commit → push

git checkout -b feature/dashboard
# create dashboard.html → add → commit → push
```

**Tip:** Always start a feature branch from an up-to-date `main`.

## 3. How to Create a Pull Request (Step by Step)

1. After `git push -u origin feature/sign-up`, GitHub usually shows a “Compare & pull request” button.
2. Go to your repository on GitHub → Click **Pull requests** → **New pull request**.
3. Set **base** branch = `main` and **compare** branch = `feature/sign-up`.
4. Write a clear **title** (example: “Add sign-up page”).
5. Write a short **description** of what the PR does.
6. Click **Create pull request**.

**Good PR title examples:** “Add sign-up page”, “Add sign-in form”, “Create dashboard layout”  
**Avoid:** “update”, “changes”, “fix”, “asdf”

## 4. How to Comment or Review a Pull Request

A reviewer (manager, teammate, or mentor) opens the PR and can:

- Read the changed files (Files changed tab).
- Leave comments on specific lines of code.
- Leave a general comment in the Conversation tab.
- Request changes, Approve, or Comment.

As the author you will see the comments under the PR.  
You do **not** close the PR. You fix the issues and push new commits to the **same branch**.

## 5. How to Rework a PR After Review Comments

This is one of the most important professional skills.

```bash
# Make sure you are on the same feature branch
git checkout feature/sign-up

# Make the requested changes in the files
git add .
git commit -m "Address review: fix form validation and button text"

# Push to the SAME branch – the PR updates automatically
git push origin feature/sign-up
```

**Important:** Do **not** create a new branch or a new PR.  
Pushing to the existing feature branch automatically updates the open Pull Request.

## 6. How to Merge a Pull Request

1. Open the Pull Request on GitHub.
2. Confirm that all conversations are resolved and the PR is approved (if required).
3. Click the green **Merge pull request** button.
4. Choose the merge strategy (usually “Create a merge commit” while learning).
5. Confirm the merge.
6. GitHub will show “Pull request successfully merged and closed”.


## 7. Delete the Remote Feature Branch

After the PR is merged, the feature branch is no longer needed on GitHub.

- GitHub often shows a “Delete branch” button right after merging – click it.
- Or go to the Branches page of the repository and delete it there.
- You can also delete from the terminal:

```bash
git push origin --delete feature/sign-up
```

## 8. Update Local main After PR is Merged

The merge happened on GitHub. Your local `main` is still old. You must bring the new commits down.

### Method A – Two commands (as shown in class)

```bash
git checkout main
git fetch origin main
git merge origin/main
```

### Method B – One command (git pull)

```bash
git checkout main
git pull origin main
```

Both methods achieve the same result.  
`git pull` = `git fetch` + `git merge`.

## 9. Delete the Local Feature Branch

After the work is safely on main, clean up your local branches.

```bash
# Make sure you are NOT on the branch you want to delete
git checkout main

# Delete the local feature branch
git branch -d feature/sign-up

# If Git complains (rare after PR merge), force delete:
git branch -D feature/sign-up
```

- `-d` = safe delete (Git checks that the branch is merged)  
- `-D` = force delete (use only when you are sure)

## 10. Full Hands-on Example Summary (feature/sign-up)

```bash
# 1. Prepare
git checkout main && git pull origin main

# 2. Feature work
git checkout -b feature/sign-up
# create sign-up.html
git add sign-up.html
git commit -m "Add sign-up page"
git push -u origin feature/sign-up

# 3. On GitHub: Create Pull Request → Review → (Rework if needed) → Merge

# 4. Cleanup remote (GitHub button or)
git push origin --delete feature/sign-up

# 5. Update local main
git checkout main
git fetch origin main
git merge origin/main

# 6. Delete local branch
git branch -d feature/sign-up
```

Repeat the same flow for `feature/sign-in` and `feature/dashboard`.

## 11. Important Rules to Remember

- Always start feature branches from an updated `main`.
- One feature / one branch / one Pull Request (keeps reviews focused).
- After review comments → fix on the **same branch** and push again (do not open a new PR).
- Merge happens on GitHub; then you must update your local `main`.
- Delete remote branch after merge (keeps repository clean).
- Delete local branch after you have updated main.
- Never force-push to `main`.

## Quick Revision Cheat Sheet

| Command / Action                              | Purpose                                      |
|-----------------------------------------------|----------------------------------------------|
| `git checkout -b feature/name`                | Create and switch to feature branch          |
| `git push -u origin feature/name`             | Push new branch and set upstream             |
| Create Pull Request on GitHub                 | Request to merge feature into main           |
| Push more commits to same branch              | Update the open PR after review              |
| Merge pull request (GitHub)                   | Merge feature into main on GitHub            |
| `git push origin --delete feature/name`       | Delete remote feature branch                 |
| `git fetch origin main`                       | Download latest main without merging         |
| `git merge origin/main`                       | Merge remote main into current branch        |
| `git pull origin main`                        | Fetch + merge in one step                    |
| `git branch -d feature/name`                  | Delete local feature branch (safe)           |
| `git branch -D feature/name`                  | Force delete local branch                    |

## Key Takeaway

- **Create branch → Commit → Push → Open PR**
- **Review → Rework on same branch → Push again**
- **Merge PR on GitHub → Delete remote branch**
- **Update local main (fetch + merge or pull) → Delete local branch**
