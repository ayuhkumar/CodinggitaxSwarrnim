
#  Basic Git Commands  


---

## Learning Goals

By the end of this session, you should be able to:

- Clone a repository from GitHub
- Understand the difference between **Clone** and **Fork**
- Use `git status` to check the state of your repository
- Stage files using `git add`
- Create commits using `git commit`
- Push commits to GitHub using `git push`

---

## 1. Clone vs Fork (Practical Understanding)

### 1.1 What is Clone?

**Clone** means making a complete copy of a remote repository (from GitHub) to your **local computer**.

- Downloads all project files + complete history
- Creates a local repository linked to the remote
- You can start working immediately after cloning

**Command:**
```bash
git clone <repository-url>
```

**Example:**
```bash
git clone https://github.com/username/project-name.git
```

After cloning:
```bash
cd project-name
```

---

### 1.2 What is Fork?

**Fork** means creating a personal copy of **someone else’s repository** on **your own GitHub account**.

- It is done on the **GitHub website** (not through terminal)
- After forking, the repository appears under your account
- You can then **clone your forked repository** and work freely
- Commonly used when contributing to open-source projects

---

### 1.3 Difference between Clone and Fork

| Point                | Clone                              | Fork                                      |
|----------------------|------------------------------------|-------------------------------------------|
| Where it happens     | On your local computer             | On GitHub (website)                       |
| What you get         | Local copy of a repository         | Copy of repository under your GitHub account |
| Command / Action     | `git clone <url>`                  | Click “Fork” button on GitHub             |
| Purpose              | Start working on a project locally | Contribute to someone else’s project      |
| Internet needed later| Yes (for push/pull)                | Yes                                       |
| Linked to original?  | Yes (remote is set automatically)  | Yes (but under your account)              |

> **Simple memory tip:**  
> **Fork** = Copy on GitHub  
> **Clone** = Copy on your computer

## 2. git status

`git status` shows the current state of your working directory and staging area.

**Command:**
```bash
git status
```

### Common messages and their meaning:

| Message                            | Meaning                                              |
|------------------------------------|------------------------------------------------------|
| Untracked files                    | New files that Git is not tracking yet               |
| Changes not staged for commit      | Tracked files are modified but not staged            |
| Changes to be committed            | Files are staged and ready for commit                |
| Working tree clean                 | No changes pending (everything is committed)         |

**Best Practice:**  
Always run `git status` before adding or committing files.

---

## 3. git add (Staging)

`git add` moves changes from the **Working Directory** to the **Staging Area**.

Only staged files will be included in the next commit.

### Commands:

```bash
# Stage a specific file
git add index.html

# Stage multiple files
git add file1.html file2.css

# Stage all changes in the current directory
git add .
```

**Flow:**
```
Working Directory  →  git add  →  Staging Area
```

---

## 4. git commit

`git commit` creates a permanent snapshot of the staged changes in your **local repository**.

- It does **not** upload anything to GitHub
- Every commit should have a clear message

**Command:**
```bash
git commit -m "Meaningful message"
```

### Good Commit Messages:
- `"Added login page"`
- `"Fixed navbar alignment"`
- `"Updated student details form"`
- `"Added README file"`

### Bad Commit Messages (Avoid):
- `update`
- `changes`
- `final`
- `test`
- `done`

**Flow:**
```
Staging Area  →  git commit  →  Local Repository
```

---

## 5. git push

`git push` uploads your local commits to the **remote repository** on GitHub.

**Basic Command:**
```bash
git push origin main
```

| Part     | Meaning                          |
|----------|----------------------------------|
| `git push` | Send commits to remote         |
| `origin`   | Name of the remote             |
| `main`     | Name of the branch             |

### First time push (recommended):
```bash
git push -u origin main
```
- The `-u` flag sets the upstream tracking relationship
- After this, you can simply use `git push` next time

---

## 6. Complete Basic Workflow (Very Important)

```bash
# 1. Clone the repository (if not already done)
git clone <repository-url>
cd repository-name

# 2. Check status
git status

# 3. Make changes in files

# 4. Stage the changes
git add .

# 5. Check status again
git status

# 6. Commit the changes
git commit -m "Added new feature"

# 7. Push to GitHub
git push origin main
```

---

## 7. Movement of Changes in Git

| Command       | From                  | To                     |
|---------------|-----------------------|------------------------|
| `git add`     | Working Directory     | Staging Area           |
| `git commit`  | Staging Area          | Local Repository       |
| `git push`    | Local Repository      | Remote Repository (GitHub) |

---

## 8. Key Points to Remember

1. **Fork** is done on GitHub website → **Clone** is done on your computer.
2. Always check `git status` before and after staging.
3. `git add` only prepares files — it does not save the version.
4. `git commit` saves the version **locally**.
5. `git push` uploads the saved commits to GitHub.
6. Write clear and meaningful commit messages.
7. Use `git push -u origin main` for the first push.

---

## 9. Quick Revision Table

| Command                  | Purpose                              |
|--------------------------|--------------------------------------|
| `git clone <url>`        | Copy remote repo to local system     |
| `git status`             | Check current state of repository    |
| `git add .`              | Stage all changes                    |
| `git add filename`       | Stage a specific file                |
| `git commit -m "msg"`    | Save snapshot locally                |
| `git push origin main`   | Upload commits to GitHub             |
| `git push -u origin main`| First push + set upstream            |

---

## 10. Key Takeaway

> **Fork** → Copy on GitHub  
> **Clone** → Copy on your computer  

> **git add** = Prepare changes  
> **git commit** = Save changes locally  
> **git push** = Upload changes to GitHub
