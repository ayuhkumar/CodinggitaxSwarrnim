

# Git Workflow and Troubleshooting


## Learning Goals

By the end of this topic, you should be able to:

- Understand and use important Git commands
- Clearly differentiate between **Git Configuration** and **GitHub Authentication**
- Follow the complete basic workflow (clone → status → add → commit → push)
- Understand how changes move between Working Directory, Staging Area, Local Repository, and Remote
- Check and manage GitHub authentication

---

## 1. Important Git Commands (Detailed Explanation)

### 1. `git clone <repository-url>`
- **Purpose:** Copies a remote repository from GitHub to your local system.
- Creates a complete local copy of the project including all files and commit history.
- After cloning, you can start working on the project offline.

**Example:**
```bash
git clone https://github.com/username/project-name.git
```

---

### 2. `git status`
- **Purpose:** Shows the current state of your repository.
- Tells you which files are:
  - **Untracked** → New files Git is not tracking yet
  - **Modified but not staged** → Tracked files that were changed
  - **Staged (ready to commit)** → Files added using `git add`
  - **Working tree clean** → No changes pending

**Always run this command** before adding or committing.

---

### 3. `git add file1 file2` **or** `git add .`
- **Purpose:** Moves changes from the **Working Directory** to the **Staging Area**.
- Only staged files will be included in the next commit.

| Command | Meaning |
|---------|---------|
| `git add index.html` | Stage only one specific file |
| `git add file1.txt file2.txt` | Stage multiple specific files |
| `git add .` | Stage **all** changes in the current folder |

---

### 4. `git commit -m "Meaningful message"`
- **Purpose:** Creates a **checkpoint** (snapshot) of the staged changes in your **local repository**.
- This does **not** upload anything to GitHub.
- The message should clearly describe what was changed.

**Good examples:**
- `"Added student registration form"`
- `"Fixed login button alignment"`
- `"Updated homepage content"`

**Avoid vague messages** like: `update`, `changes`, `done`, `test`

---

### 5. `git log`
- **Purpose:** Displays the complete history of all commits.
- Shows:
  - Commit ID (long hash)
  - Author name and email
  - Date and time
  - Commit message

---

### 6. `git log --oneline`
- **Purpose:** Shows a short and clean version of the commit history.
- Displays only:
  - Short commit ID
  - Commit message
- Very useful for quick revision of history.

---

### 7. `git push origin main`
- **Purpose:** Uploads your local commits to the remote GitHub repository.
- `origin` → name of the remote
- `main` → name of the branch

**First time push (recommended):**
```bash
git push -u origin main
```
The `-u` flag sets the upstream so that next time you can simply use `git push`.

---

### 8. `git remote -v`
- **Purpose:** Shows the remote repository URL linked to your local project.
- Helps you confirm whether the correct GitHub repository is connected.
- Output usually looks like:
  ```
  origin  https://github.com/username/repo.git (fetch)
  origin  https://github.com/username/repo.git (push)
  ```

---

### 9. `gh auth status`
- **Purpose:** Shows which GitHub account is currently authenticated.
- Useful when you get permission errors (403).

> Requires **GitHub CLI (`gh`)** to be installed.

---

### 10. `gh auth login`
- **Purpose:** Login to GitHub or switch to a different account.
- Use this when you are logged in with the wrong account.

---

## 2. Git Configuration vs GitHub Authentication (Detailed)

These two concepts are often confused by beginners. They solve **different problems**.

### A. Git Configuration

| Aspect | Details |
|--------|---------|
| **What it does** | Sets your identity (name & email) for commits |
| **Commands** | `git config --global user.name "Your Name"` <br> `git config --global user.email "your@email.com"` <br> `git config --list` |
| **How it is done** | Using Git commands |
| **Purpose** | Answers the question: **Who created this commit?** |
| **Gives push permission?** | **No** |

**Important:**  
Changing your name or email only affects how your name appears in commit history. It does **not** log you into GitHub.

---

### B. GitHub Authentication

| Aspect | Details |
|--------|---------|
| **What it does** | Verifies your identity when accessing GitHub |
| **Commands** | `gh auth status` <br> `gh auth login` |
| **How it is done** | Git Credential Manager / Browser sign-in / GitHub CLI |
| **Purpose** | Answers the question: **Who is trying to access GitHub?** |
| **Gives push permission?** | **Yes** (only if the account has write access) |

**Important:**  
Even if your Git name and email are correct, you cannot push unless the correct GitHub account is authenticated and has permission.

---

### Summary Table

| Feature | Git Configuration | GitHub Authentication |
|---------|-------------------|-----------------------|
| Identity for commits | Yes | No |
| Access control to GitHub | No | Yes |
| Done by | `git config` commands | Credential Manager / `gh auth` |
| Required for commit | Yes | No |
| Required for push | No | Yes |

## 3. Complete Basic Workflow (Step-by-Step)

```bash
# Step 1: Get the project from GitHub
git clone <repository-url>

# Step 2: Check current status
git status

# Step 3: Stage all changes
git add .

# Step 4: Create a local commit (snapshot)
git commit -m "Meaningful message"

# Step 5: View commit history
git log --oneline

# Step 6: Upload commits to GitHub
git push origin main
```

---

## 4. How Changes Move in Git

Understanding this flow is very important:

```
Working Directory
       ↓  (git add)
Staging Area
       ↓  (git commit)
Local Repository
       ↓  (git push)
Remote Repository (GitHub)
```

| Command | From | To |
|---------|------|----|
| `git add` | Working Directory | Staging Area |
| `git commit` | Staging Area | Local Repository |
| `git push` | Local Repository | GitHub (Remote) |

---

## 5. Common Errors & Quick Checks

### 403 Permission Denied
- Meaning: GitHub understood the request but refused access.
- Common reasons:
  - Wrong GitHub account is authenticated
  - You don’t have write permission
  - Remote URL points to someone else’s repository

**What to check:**
```bash
git remote -v
gh auth status
git config --global user.name
git config --global user.email
```

---

## 6. Key Takeaways

1. **`git add`** → Prepare changes  
2. **`git commit`** → Save changes **locally**  
3. **`git push`** → Upload commits to **GitHub**

4. **Git Configuration** = Who wrote the commit  
5. **GitHub Authentication** = Who is allowed to push  

> **Configuration ≠ Authentication ≠ Permission**
